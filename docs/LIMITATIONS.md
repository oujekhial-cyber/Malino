# محدودیت‌ها و موارد باقی‌مانده

## محدودیت‌های سیستم‌عامل (خارج از کنترل برنامه)

- پس از **Force Stop** توسط کاربر، اندروید Broadcast پیامک را به برنامه نمی‌رساند تا برنامه دوباره باز شود.
- سازنده‌های با مدیریت باتری تهاجمی (Xiaomi/MIUI، Huawei، …) ممکن است Receiver یا Worker را محدود کنند؛ لازم است کاربر برنامه را از بهینه‌سازی باتری مستثنا کند.
- Heads-up اعلان و رفتار صفحه قفل تابع تنظیمات دستگاه است و تضمین نمی‌شود.
- روی صفحه قفل، به‌صورت طراحی‌شده جزئیات مالی مخفی است.
- «بازشدن خودکار تمام‌صفحه» هنگام دریافت پیامک عمداً پیاده‌سازی نشده (مغایر سیاست‌های اندروید برای اپ مالی).

## محدودیت‌های نسخه فعلی

- **آزمایش روی دستگاه/شبیه‌ساز واقعی انجام نشده است.** محیط ساخت فاقد شبیه‌ساز بود؛ Build و تست‌های واحد در CI اجرا شده‌اند ولی تست Instrumentation و اسکرین‌شات واقعی موجود نیست.
- انتخاب تاریخ شمسی با فیلدهای عددی (سال/ماه/روز) انجام می‌شود؛ تقویم گرافیکی ماهانه هنوز ساخته نشده.
- تطبیق انتقال داخلی فقط حالت «تک‌کاندید» را خودکار وصل می‌کند؛ در حالت چندکاندید گروه ناقص ساخته می‌شود و اتصال دستی سمت مقابل UI اختصاصی ندارد (از طریق ویرایش تراکنش قابل مدیریت است).
- نمودار موجودی حساب در طول زمان هنوز پیاده نشده (فقط «مانده اعلام‌شده پیامک» با منبع و زمان در جزئیات تراکنش نمایش داده می‌شود).
- Merge در Restore پشتیبانی نمی‌شود؛ فقط «جایگزینی کامل با تأیید».
- بازه دلخواه (از تاریخ X تا Y) در گزارش‌ها هنوز UI ندارد؛ روز/هفته/ماه/سال شمسی موجود است.
- انتخاب مستقیم محدوده متن (text selection) در آموزش قالب پیاده نشده؛ به‌جای آن انتخاب از فهرست اعداد/واژه‌های استخراج‌شده (که در مشخصات به‌عنوان جایگزین مجاز ذکر شده بود).
- پنجره شناور روی سایر برنامه‌ها (SYSTEM_ALERT_WINDOW) عمداً ساخته نشده — جزو الزامات نبود.
- خروجی Excel، نمودار دایره‌ای/میله‌ای — طبق مشخصات جزو الزامات نسخه اول نیستند.
- آیکون برنامه یک آیکون وکتوری ساده (کیف پول) است؛ نام و آیکون از `app_label` در `app/build.gradle.kts` و `res/drawable/ic_launcher_*` به‌سادگی قابل تغییرند.
- ابزار شبیه‌سازی پیامک داخل برنامه ساخته نشده؛ برای تست دستی روی شبیه‌ساز می‌توان از `adb emu sms send <sender> <text>` استفاده کرد (فقط شبیه‌ساز).

## نکات امنیتی شفاف

- قفل برنامه فقط UI را می‌بندد؛ دیتابیس Room رمزنگاری‌شده نیست (در فضای خصوصی برنامه است). رمزنگاری کامل DB (مثل SQLCipher) در نسخه اول انجام نشده و به‌عنوان کار آینده مستند می‌شود.
- خروجی PDF رمزنگاری نشده است و این موضوع در UI به کاربر یادآوری می‌شود.

## کارهای پیشنهادی آینده

1. تقویم شمسی گرافیکی برای انتخاب تاریخ و بازه دلخواه گزارش
2. UI اتصال دستی دو سمت انتقال و مدیریت گروه‌های ناقص
3. نمودار موجودی برآوردی حساب (با برچسب صریح «برآوردی»)
4. تست‌های Instrumentation و Compose UI روی شبیه‌ساز
5. رمزنگاری دیتابیس با SQLCipher و کلید Keystore
6. Merge هوشمند در Restore
