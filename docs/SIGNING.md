# امضای نسخه انتشار خرج‌یار

این سند توضیح می‌دهد کلید امضا چیست، چرا مهم است و چطور نسخه انتشار ساخته می‌شود.

## چرا کلید امضا مهم است

هر برنامه اندروید با یک کلید دیجیتال امضا می‌شود. اندروید فقط به‌روزرسانی‌هایی را
می‌پذیرد که **با همان کلید نسخه قبلی** امضا شده باشند.

> ⚠️ **اگر کلید گم شود، دیگر هرگز نمی‌توان برای این برنامه به‌روزرسانی منتشر کرد.**
> کاربران مجبور می‌شوند نسخه قدیمی را حذف و از نو نصب کنند — یعنی همه داده‌هایشان
> (حساب‌ها، تراکنش‌ها، دسته‌بندی‌ها) از بین می‌رود.
>
> پس از دریافت کلید، حتماً یک نسخه پشتیبان در جای امن نگه دارید.

## مشخصات کلید فعلی

| ویژگی | مقدار |
|---|---|
| نوع | RSA ۴۰۹۶ بیتی |
| الگوریتم امضا | SHA-256 |
| نام مستعار (alias) | `kharjyar` |
| صاحب گواهی | CN=Rahim Karami, OU=KharjYar, O=KharjYar, L=Tehran, C=IR |
| تاریخ انقضا | ۱۴ سپتامبر ۲۰۵۶ (حدود ۳۰ سال) |
| اثر انگشت SHA-256 | `C8:B9:DC:B5:97:27:57:E2:B7:5C:BA:6E:D3:2D:67:F6:02:78:C0:BB:40:95:C9:AF:E3:F5:8D:15:88:71:69:3F` |

اثر انگشت بالا هویت دائمی برنامه است. هر APK سالمی که منتشر می‌کنید باید همین
اثر انگشت را داشته باشد؛ اگر روزی فرق داشت، یعنی با کلید دیگری امضا شده است.

## کلید کجاست

فایل کلید در پوشه `.keys/` تولید شده و **عمداً وارد مخزن گیت نشده است**
(از طریق `.gitignore` مسدود شده). این پوشه شامل:

| فایل | توضیح |
|---|---|
| `kharjyar-release.p12` | خودِ کلید (فرمت استاندارد PKCS#12) |
| `keystore.b64` | همان کلید به شکل متنی، برای ثبت در GitHub Secret |
| `.pw.txt` | رمز کلید |
| `kharjyar.cert.pem` | گواهی عمومی (حساس نیست) |
| `kharjyar.key.pem` | کلید خصوصی خام |

## راه‌اندازی ساخت خودکار در GitHub

ساخت نسخه انتشار در CI نیاز به چهار Secret دارد. آن‌ها را از مسیر زیر اضافه کنید:

**Settings ← Secrets and variables ← Actions ← New repository secret**

| نام Secret | مقدار |
|---|---|
| `KEYSTORE_B64` | کل محتوای فایل `.keys/keystore.b64` |
| `KEYSTORE_PASSWORD` | رمز موجود در `.keys/.pw.txt` |
| `KEY_ALIAS` | `kharjyar` |
| `KEY_PASSWORD` | همان رمز `KEYSTORE_PASSWORD` |

پس از افزودن این چهار مورد، هر push به شاخه کاری، فایل
`dist/KharjYar-release.apk` را امضاشده با کلید اختصاصی تولید می‌کند.

**تا وقتی Secretها اضافه نشده‌اند** ساخت متوقف نمی‌شود؛ فقط نسخه انتشار با کلید
debug امضا می‌شود. فایل `dist/build-report.md` در خط «کلید اختصاصی» وضعیت را
گزارش می‌دهد (`true` یعنی کلید شما استفاده شده است).

## ساخت روی کامپیوتر شخصی

فایل `local.properties` را در ریشه پروژه بسازید (این فایل هم در `.gitignore` است):

```properties
kharjyar.storeFile=/مسیر/کامل/به/kharjyar-release.p12
kharjyar.storePassword=رمز_کلید
kharjyar.keyAlias=kharjyar
kharjyar.keyPassword=رمز_کلید
```

سپس:

```bash
./gradlew :app:assembleRelease
```

خروجی در `app/build/outputs/apk/release/app-release.apk` قرار می‌گیرد.

## بررسی امضای یک APK

```bash
$ANDROID_HOME/build-tools/35.0.0/apksigner verify --print-certs app-release.apk
```

اثر انگشت SHA-256 خروجی باید با جدول بالا یکی باشد.

## درباره هشدار Play Protect

هنگام نصب دستی ممکن است پیام «App blocked to protect your device» را ببینید.
این پیام خطا یا ویروس نیست؛ معنایش این است که گوگل قبلاً برنامه‌ای از این
توسعه‌دهنده ندیده است. با زدن **Install anyway** برنامه سالم نصب می‌شود.

امضا با کلید اختصاصی این هشدار را کمتر می‌کند، ولی تنها راه حذف کامل آن،
انتشار برنامه در Google Play یا کافه‌بازار است.

## تفاوت نسخه debug و release

| | debug | release |
|---|---|---|
| حجم | حدود ۸۰ مگابایت | به‌مراتب کمتر (کد بلااستفاده حذف می‌شود) |
| سرعت | کندتر | بهینه‌شده |
| کد | خوانا | مبهم‌سازی‌شده (R8) |
| لاگ‌ها | فعال | کاملاً حذف‌شده تا اطلاعات مالی نشت نکند |
| معماری | شامل x86 شبیه‌ساز | فقط ARM گوشی‌های واقعی |

برای استفاده روزمره **همیشه نسخه release** را نصب کنید.
